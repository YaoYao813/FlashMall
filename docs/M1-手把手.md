# M1 手把手（给人看的）

> 这份不是给 Claude Code 看的，是给你看的。
> 目标是：**你不需要看懂代码，也能判断「这一步做完了没有」。**
> M1 做完就可以删掉这份文件。

## 先记住一件事

M1 这两天只干三件事，**全部是 Java**：

1. 在数据库里建两张表
2. 加一个能查「秒杀活动」表的工具类（Mapper）
3. 写三个 HTTP 接口

**和 LangGraph、MCP、Agent 一点关系都没有。** 那些是 11/09 以后的事。

## 名词对照（M1 只会遇到这些）

| 名词 | 一句话 |
|---|---|
| **Mapper** | MyBatis-Plus 的接口。继承 `BaseMapper<T>` 就自动有增删改查，一行 SQL 都不用写 |
| **VO** | 返回给前端的对象。只挑前端要的字段，不是数据库实体 |
| **Controller** | 接 HTTP 请求的类 |
| **Service** | 写业务逻辑的类 |
| **幂等键** | 同一个请求重复发，只生效一次 |
| **回放** | 重复请求时不执行第二次，直接把上次的结果返回 |
| **状态推导** | 表里没有 status 字段，用起止时间现算 |
| **迁移脚本** | 建表用的 SQL 文件 |

## 怎么问会话（固定句式）

看不懂代码时，用这三句，比「这是什么意思」有效得多：

- 「这个类在整个链路里被谁调用？一句话说。」
- 「如果删掉这个方法，会发生什么？」
- 「这 10 行逐行解释，每行不超过 15 个字。」

## 判断「这步做完了没有」

每一步只有一个标准：**能不能看见一个具体结果。**

| 步骤 | 看得见的结果 |
|---|---|
| 编译 | `BUILD SUCCESS` |
| 建表 | `SHOW TABLES` 出两行 |
| Mapper | 编译通过 |
| 状态 | 测试全绿 |

看不见结果 = 没做完。不要靠「应该差不多」。
